# V21e3r1 implementation-independent algorithm replay protocol v1

## 1. Status and authority boundary

This package has the following exact status:

```text
PACKAGE_STATUS = DESIGN_AND_GOLDEN_CORPUS_ONLY
NEUTRAL_COMPARATOR_AVAILABLE = true
REFERENCE_ALGORITHM_PRODUCER_AVAILABLE = false
EXTERNAL_PRODUCER_PRESENT = false
IMPLEMENTATION_INDEPENDENCE = false
THIRD_PARTY_INDEPENDENCE = false
SCIENTIFIC_INDEPENDENCE = false
FORMAL_AUTHORITY = false
SELECTION_AUTHORITY = false
CONFIRMATION_AUTHORITY = false
```

The executable in this directory is a neutral, Python-standard-library-only
validator and comparator for two producer event streams. It does not execute a
V21e3r1 optimizer, import `mo_nco`, authenticate a producer, verify physical
custody, or provide an independently written producer. The golden files are
synthetic protocol fixtures. In particular,
`golden/external_valid.jsonl` is a differently labelled placeholder fixture,
not evidence that an external implementation or investigator exists.

A PASS from the comparator proves only that both supplied streams individually
satisfy this protocol and have equal neutral event projections. It cannot by
itself prove that the streams were generated by different code, on different
machines, prospectively, or by an external party. It cannot authorize
selection, confirmation, a formal study, an IJOC claim, or submission.

## 2. Normative vocabulary and artifacts

The words MUST, MUST NOT, REQUIRED, SHALL, SHALL NOT, SHOULD, and MAY are used in
their ordinary protocol sense. Version 1 has four artifact classes:

1. a frozen algorithm specification identified by
   `algorithm_spec_sha256`;
2. a frozen case artifact and independently defined semantic problem identity;
3. one canonical JSONL event stream from each producer;
4. one exclusive-create comparator receipt.

The comparator consumes exactly two streams, named `reference` and `candidate`
for role clarity. Those names make no independence claim. Either stream may be
invalid, copied, fabricated, or generated by shared code; custody review is a
separate gate.

## 3. Canonical JSON and exact types

Each stream MUST be nonempty UTF-8 without a BOM. Records MUST be separated by
a single LF byte, blank records and CR bytes are forbidden, and the file MUST
end in LF. Each line is one JSON object with no duplicate keys.

The canonical encoding function `C(x)` is defined as follows:

1. object keys are sorted by Unicode code-point order;
2. separators are exactly `,` and `:` with no insignificant whitespace;
3. strings are encoded directly as UTF-8 JSON strings, not forced to ASCII
   escapes;
4. JSON `NaN`, `Infinity`, and `-Infinity` are forbidden;
5. JSON floating-point tokens are forbidden everywhere;
6. integer fields use JSON integer tokens and Boolean values are never accepted
   as integers;
7. scientifically numeric noninteger values use canonical decimal strings.

A canonical decimal string matches
`-?(0|[1-9][0-9]*)(\.[0-9]*[1-9])?`, except that `-0` is forbidden. Therefore
`0`, `-5`, `0.25`, and `-0.25` are valid; `00`, `1.0`, `1e-3`, `+1`, and JSON
number `0.25` are invalid. This avoids cross-language binary-float formatting
ambiguity.

All digests are lowercase, 64-character SHA-256 hex strings. Unless stated
otherwise, a structured digest is `sha256(C(x))`. Exact-key validation applies
to every protocol event and nested source/proposal/context object: missing and
extra keys are equally invalid.

## 4. Source, case, configuration, and context binding

### 4.1 Producer source manifest

Each manifest event embeds one exact source manifest:

```json
{
  "schema": "v21e3r1_external_source_manifest_v1",
  "implementation_id": "producer-chosen-stable-id",
  "language": "producer-language-and-toolchain-id",
  "files": [
    {"path": "relative/posix/path", "sha256": "..."}
  ],
  "source_root_sha256": "..."
}
```

`files` MUST be nonempty, unique, and sorted by normalized relative POSIX path.
Absolute paths, backslashes, `.` segments, and `..` segments are forbidden.
The exact binding is:

```text
source_root_sha256 = sha256(C(files))
producer_source_manifest_sha256 = sha256(C(producer_source_manifest))
```

The comparator validates both equations. It does not receive or rehash the
listed source files. External custody MUST separately establish that every
delivered file byte string matches its listed digest; a self-declared source
manifest is a binding target, not proof of authorship or independence.

### 4.2 Case binding

The manifest contains both:

* `case_artifact_sha256`: SHA-256 of the exact case artifact bytes supplied to
  the producer;
* `problem_semantic_sha256`: SHA-256 defined by the frozen algorithm/case
  specification over the language-neutral semantic problem representation.

Every evaluation repeats `problem_semantic_sha256`; the terminal repeats both
digests. The comparator checks internal repetition and equality between
producers. It does not recompute objectives from undisclosed case bytes. A real
external execution package MUST include and independently rehash those bytes.

### 4.3 Exact configuration binding

`algorithm_config` contains only JSON exact types permitted in section 3.
`algorithm_config_schema` is a nonempty, unique, lexicographically sorted list
of its exact keys. The key sets MUST be equal, and:

```text
candidate_config_sha256 = sha256(C(algorithm_config))
```

The following mirrored fields are mandatory and exactly typed:

```text
algorithm_config.candidate_id        == manifest.candidate_id
algorithm_config.charged_evaluations == manifest.charged_evaluation_budget
algorithm_config.phase               == manifest.evidence_partition
algorithm_config.rng_protocol        == manifest.rng_protocol
algorithm_config.seed                is a nonnegative JSON integer, not Boolean
```

A producer cannot legitimize an extra configuration key merely by recomputing
`candidate_config_sha256`; it must also change the prospectively frozen exact
schema, which changes the neutral manifest projection and therefore fails
comparison against the frozen reference.

### 4.4 Run context

The run context material is the canonical object containing these manifest
fields in their exact values:

```text
producer_id
producer_source_manifest
producer_source_manifest_sha256
algorithm_spec_sha256
case_artifact_sha256
problem_semantic_sha256
problem_family
algorithm_config
algorithm_config_schema
candidate_config_sha256
candidate_id
evidence_partition
charged_evaluation_budget
objective_count
rng_protocol
rng_vector_length
rng_vector_sha256
```

`context_sha256 = sha256(C(context material))`. Every event repeats that exact
digest. Context digests normally differ between producers because producer and
source identities are intentionally included.

## 5. Language-neutral frozen RNG tape

Version 1 uses `frozen-u64-tape-v1`. The RNG tape is an input artifact, not an
implementation-specific PRNG claim. The `rng_vector` event contains a list of
unsigned 64-bit values encoded as exactly 16 lowercase hexadecimal characters.
The list length and `sha256(C(values))` MUST equal the bindings in the manifest.

Producers SHALL consume the same tape from index zero. Each attempt records a
half-open `[rng_start, rng_stop)` span. Attempt spans MUST be contiguous, may be
empty, and cannot exceed the tape. The terminal MUST report consumption of the
entire frozen vector. Hidden draws, skipped draws, and unused suffixes fail.

When a frozen algorithm specification needs standard random primitives, it
SHALL define them from the tape as follows:

* `next_u64()` decodes the next 16-hex word as an unsigned integer in
  `[0, 2^64)` and advances the cursor once;
* `randbelow(n)` for positive integer `n` sets
  `limit = 2^64 - (2^64 mod n)`, repeatedly consumes `u = next_u64()` until
  `u < limit`, and returns `u mod n`;
* a Fisher-Yates shuffle visits indices from `length-1` down to `1` and swaps
  with `randbelow(i+1)`;
* a Bernoulli decision with exact rational threshold `p/q` succeeds exactly
  when `randbelow(q) < p`;
* sampling without replacement is the prefix of the specified Fisher-Yates
  order.

An algorithm version that needs another transformation MUST freeze it in a new
algorithm specification before generating selection or confirmation data. The
neutral comparator validates tape identity, spans, and emitted operator
witnesses; it is not an independent implementation of the producer's control
flow.

## 6. Event grammar and hash chain

The only successful stream grammar is:

```text
manifest -> rng_vector -> { attempt [ evaluation decision ] }+ -> terminal
```

The bracketed pair is present exactly when the attempt status is `EVALUATED`.
A `CACHE_HIT` attempt has neither a new evaluation nor a decision. Event indices
start at zero and are contiguous. For the manifest,
`prev_event_sha256` is 64 zeroes. For every later event it equals the preceding
event's `event_sha256`.

For every event `e`, define `core(e)` by removing only `event_sha256`. Then:

```text
event_sha256 = sha256(C(core(e)))
```

Recomputing only a downstream hash is insufficient: the predecessor link,
context binding, event grammar, exact event keys, accounting identities, and
the second producer's neutral projection must all agree.

### 6.1 Manifest event

The manifest freezes all section 4 bindings, the problem family (`MOKP` or
`MOTSP`), objective count, evidence partition, exact charged-evaluation budget,
and RNG vector identity. The manifest is first and unique.

### 6.2 RNG-vector event

The RNG vector is second and unique. Its exact values, length, and digest agree
with the manifest. Formal packages SHOULD place the same tape in a separately
hashed custody artifact so both producers can consume identical bytes without
sharing executable code.

### 6.3 Attempt event

Attempts are one-based and contiguous. Every attempt includes:

* the canonical proposal and its SHA-256;
* exact evaluation context: evidence partition, phase, stage, type, operator,
  operator-call index, local-search depth, retry ordinal, fallback flag, and an
  operator witness;
* exact RNG start and stop cursors;
* status and physical/charged/cache accounting.

MOKP proposals use `mokp-bits-v1` and a nonempty list of exact `0`/`1`
integers. MOTSP proposals use `motsp-permutation-v1` and an exact permutation of
`0..n-1`. Proposal identity is `sha256(C(proposal))`.

An `EVALUATED` attempt starts exactly one physical call, carries the next
charged evaluation index, has no cache source, and its proposal has not been
evaluated earlier. A `CACHE_HIT` starts no physical call, carries no charged
index, and identifies the earlier evaluation of the identical proposal.

### 6.4 Evaluation event

Every evaluated attempt is immediately followed by one evaluation. The event
repeats the attempt/proposal identity and the exact semantic problem digest.
Partition, phase, stage, type, operator, and operator-call index exactly mirror
the attempt context. The objective vector has the frozen objective count and
uses canonical decimal strings only.

### 6.5 Decision event

Every evaluation is immediately followed by exactly one decision. The event
binds all of the following, rather than checking only objective/archive output:

* accepted/rejected population status;
* exact unique population replacement target set and count;
* decision reason;
* archive changed/retained status and size;
* scalarization identifier and canonical parent/candidate/advantage values;
* objective-cell identifier and evaluated/nondominated novelty flags;
* complete population-state and archive-state roots.

Scalarization ID plus parent, candidate, and advantage values are either all
present (with canonical decimal value strings) or all null. Cell ID plus both
novelty flags are likewise jointly present or jointly null. A rejected
population decision cannot report replacement targets. State-root construction
itself belongs to the frozen algorithm
specification and must be independently implemented by each producer; this
comparator compares and chain-binds the emitted roots.

### 6.6 Terminal event

The terminal is last and unique, has exact status `SUCCESS`, repeats the source,
case, semantic problem, configuration, and RNG bindings, and binds the final
population/archive roots. The comparator accepts complete success streams only;
failure and recovery require a future protocol version.

## 7. Budget and accounting protocol

Let:

```text
A = attempt count
P = physical objective calls started
B = successful first-unique charged evaluations
D = recorded decisions
C = cache-hit attempts
```

Every prefix is expected to satisfy `A >= P >= B >= D`. Version 1 success is
fault-free, so terminal completeness is stronger:

```text
P = B = D = charged_evaluation_budget
A = B + C
rng_values_consumed = rng_vector_length
```

The terminal count fields must equal counts reconstructed from the event
grammar. No padding, unrecorded objective call, free first-unique evaluation,
decision omission, or unused RNG suffix is allowed.

## 8. Neutral comparison rule

Each stream is fully validated before comparison. The neutral projection removes
only per-producer custody fields:

* `context_sha256`, `prev_event_sha256`, and `event_sha256` from every event;
* `producer_id`, `producer_source_manifest`, and
  `producer_source_manifest_sha256` from the manifest;
* `producer_source_manifest_sha256` from the terminal.

Everything else, including algorithm specification, case, semantic problem,
exact config/schema, RNG tape, proposals, operator witnesses, attempt state,
objectives, decisions, roots, counts, and terminal state, is compared exactly.

Different producer labels and source manifests are recorded as observations.
They are not sufficient evidence of independently authored code. The comparator
therefore always emits all independence and formal-authority fields as false.

## 9. Receipt and custody protocol

The output is created with exclusive create. An existing path is never
overwritten. The receipt binds each input stream's exact byte length, file
SHA-256, event count, terminal event digest, producer label, source-manifest
digest, and context digest. It contains exact comparison checks, the first
semantic mismatch witness, the fixed authority boundary, and
`receipt_payload_sha256 = sha256(C(receipt without that field))`.

For an actual external reproduction, custody MUST additionally provide:

1. immutable source files whose bytes match both embedded source inventories;
2. exact case, algorithm-specification, config, and RNG-tape artifacts;
3. independent build/runtime manifests and commands;
4. machine and investigator identities anchored outside this repository;
5. start/end timestamps or signed attestations from the independent custodian;
6. the two original event streams before comparison;
7. hashes recorded in an append-only or externally anchored channel;
8. a review that the producers share no algorithm implementation code.

Those facts belong in a separately versioned custody/independence receipt. They
must not be inferred from this neutral comparator receipt.

## 10. Executable commands

### 10.1 Golden positive and negative checks

From the repository root on Windows PowerShell:

```powershell
$python = 'C:\miniconda3\envs\ssm_env\python.exe'

& $python independent_reproduction\compare_v21e3r1_algorithm_events.py `
  --reference independent_reproduction\golden\reference_valid.jsonl `
  --candidate independent_reproduction\golden\external_valid.jsonl `
  --output golden_positive_receipt.json
# Expected exit 0 and PASS_NEUTRAL_EVENT_STREAM_COMPARISON.

& $python independent_reproduction\compare_v21e3r1_algorithm_events.py `
  --reference independent_reproduction\golden\reference_valid.jsonl `
  --candidate independent_reproduction\golden\negative_decision_mismatch.jsonl `
  --output golden_negative_receipt.json
# Expected exit 2 and FAIL_ALGORITHM_EVENT_STREAM_MISMATCH.
```

The output paths must not already exist because receipt creation is exclusive.
The positive command is a comparator/golden-corpus smoke only.

### 10.2 External producer command template

The producer commands below are deliberately placeholders; this repository does
not contain either required algorithm producer.

```bash
set -euo pipefail

REFERENCE_SOURCE_MANIFEST=/custody/reference/source_manifest.json
CANDIDATE_SOURCE_MANIFEST=/external/custody/source_manifest.json
CASE=/custody/frozen/case.json
CONFIG=/custody/frozen/config.json
RNG_TAPE=/custody/frozen/rng_u64_tape.json
REFERENCE_EVENTS=/custody/events/reference.events.jsonl
CANDIDATE_EVENTS=/external/custody/candidate.events.jsonl
RECEIPT=/custody/receipts/neutral_comparison.json

test ! -e "$REFERENCE_EVENTS"
test ! -e "$CANDIDATE_EVENTS"
test ! -e "$RECEIPT"

<reference-producer-command> \
  --source-manifest "$REFERENCE_SOURCE_MANIFEST" \
  --case "$CASE" --config "$CONFIG" --rng-tape "$RNG_TAPE" \
  --output "$REFERENCE_EVENTS"

<independently-authored-candidate-producer-command> \
  --source-manifest "$CANDIDATE_SOURCE_MANIFEST" \
  --case "$CASE" --config "$CONFIG" --rng-tape "$RNG_TAPE" \
  --output "$CANDIDATE_EVENTS"

sha256sum "$REFERENCE_SOURCE_MANIFEST" "$CANDIDATE_SOURCE_MANIFEST" \
  "$CASE" "$CONFIG" "$RNG_TAPE" "$REFERENCE_EVENTS" "$CANDIDATE_EVENTS"

python3 independent_reproduction/compare_v21e3r1_algorithm_events.py \
  --reference "$REFERENCE_EVENTS" \
  --candidate "$CANDIDATE_EVENTS" \
  --output "$RECEIPT"
```

An equivalent PowerShell comparison step is:

```powershell
$receipt = 'D:\external-custody\neutral-comparison.json'
if (Test-Path -LiteralPath $receipt) { throw 'receipt already exists' }

C:\path\to\independent-python.exe `
  independent_reproduction\compare_v21e3r1_algorithm_events.py `
  --reference D:\reference-custody\reference.events.jsonl `
  --candidate D:\external-custody\candidate.events.jsonl `
  --output $receipt
```

Exit codes are `0` for equal valid streams, `2` for two valid but unequal
streams, and `3` for an invalid/unreadable stream or an unwritable/pre-existing
receipt path.

## 11. Golden corpus

* `reference_valid.jsonl` is a synthetic one-evaluation MOKP reference stream.
* `external_valid.jsonl` is an equal neutral stream with different synthetic
  producer/source metadata. It is a placeholder, not an external reproduction.
* `negative_decision_mismatch.jsonl` is individually valid and coherently
  rehashed but changes the decision reason; comparison must return exit 2.

The tests derive further temporary negative streams from these canonical files:
noncanonical JSONL, Boolean-as-integer budget, broken predecessor chain,
source-inventory drift, extra config key, RNG drift, terminal case drift,
missing decision, missing terminal, and pre-existing output custody.

## 12. Gate to a future external reproduction

The present deliverable closes only an executable protocol-design gap. The
status may not be upgraded until all of the following exist and are reviewed:

1. a frozen, language-neutral full V21e3r1 control-flow specification covering
   operator schedules, population replacement, scalarization, cells, novelty,
   archive/state roots, retry, fallback, and stopping;
2. an independently authored reference producer and external producer;
3. verified source bytes and disjoint implementation provenance;
4. prospective case/config/RNG artifacts under independent custody;
5. successful event-stream generation without using historical result streams
   as an oracle;
6. a PASS neutral comparison and a separate authenticated custody receipt;
7. independent review of both producer implementations and the protocol;
8. a separately authorized selection/confirmation/formal-study gate.

Until then the only admissible wording is: “neutral comparator and synthetic
golden corpus implemented; external algorithm reproduction not yet performed.”
